# Работа с Викитекой

Команды ниже запускаются из корня репозитория. Данные томов по умолчанию лежат в `vols/NN/`. Переменная `WS_VOLS` задаёт другую папку. Шаблоны, названия и правила относятся к проекту БСЭ1. В новом проекте начните с [демонстрации](../README.md#попробовать-локально) и проверочной партии.

## Сверка страниц индекса по скану

Подготовьте папку партии:

- `scans/N.jpg` содержит изображение страницы. `N` означает номер страницы файла из названия `Страница:…/N`, который может отличаться от печатного номера или номера столбца.
- `ocr/N.wiki` содержит снимок текущего викитекста, включая служебную шапку и подвал.
- `model/N.wiki` содержит предлагаемый вариант целой страницы. Его может подготовить человек или модель.
- `notes.json` содержит заметки по страницам. Строки с префиксом `⚠` видны в списке мест для проверки. [Формат](formats.md#заметки-к-страницам)

```sh
bun pipeline/pilot.ts --dir review --file "Имя файла.pdf"
```

Скрипт передаёт викитекст в `action=parse` настроенного API, собирает `review/index.html` и выводит сведения об ошибках шаблонов и изменениях слов. Сверяйте со сканом порядок столбцов, цифры, имена и исторические формы слов. Для модельной подготовки пригодится [шаблон задания](proofreading-prompt.md).

Для правки существующей страницы запустите `pilot-upload.ts` с теми же аргументами. Скрипт сверяет снимок с текущим текстом, состояние вычитки, служебную разметку и включения из других статей. Публикация требует `--publish --limit N` с лимитом до пяти страниц. Для уровня 3 укажите `--reviewed` и впишите номера лично сверенных страниц в `review/reviewed.txt`. Учетная запись берётся из `WS_BOT_USER`. Журнал — `review/upload-journal.jsonl`.

## Создание статей через `<pages>`

```sh
bun pipeline/prepare.ts --vol 41 --refresh
bun pipeline/transclude.ts --vol 41
bun pipeline/upload.ts --vol 41 --manifest pages
```

`prepare.ts` сопоставляет словник со страницами и пишет `articles.jsonl` и `pages.json`. Если у тома несколько изданий, задайте `--index "часть имени файла"`. `transclude.ts` проверяет границы, страницы и текст в рендере MediaWiki. Посмотрите `pages-held.md`, `checks.jsonl` и `manifest-pages.jsonl` перед публикацией.

С `transclude.ts --offline` используются только локальные снимки и результат получает статус `local_pass`. Этот режим удаляет выходные файлы ранее построенного манифеста включений. Для статей с таблицами или иллюстрациями `transclude-complex.ts --vol 31 --titles "Название|Другое название"` запускает отдельную сверку по явно перечисленным статьям и заменяет манифест включений тома.

## Создание статей из сверенного текста

```sh
bun pipeline/prepare.ts --vol 58
bun pipeline/todo.ts --vol 58 --count 20 --scans
bun pipeline/build.ts --vol 58 --quality 2
bun pipeline/upload.ts --vol 58
```

Между `todo.ts` и `build.ts` внесите вычитанный по скану текст в `vols/58/fixed.jsonl`. Каждая строка содержит `title`, `body` и необязательную `category`. Если статья имеет статус `review`, сначала разберите её причины, затем добавьте название в `approved.txt`. Статьи со статусом `blocked` остаются вне манифеста. Для качества 3 или 4 `build.ts` требует `--reviewed` после личной проверки партии. Проверяйте допустимый уровень по правилам издания.

## Пакетная публикация

Задайте `WS_BOT_USER` и `WS_BOT_PASS` в окружении или локальном `.env` по образцу [`.env.example`](../.env.example). Для автоматического входа используйте отдельный [бот-пароль MediaWiki](https://www.mediawiki.org/wiki/Manual:Bot_passwords) с правами на нужные операции.

Сначала выполните команду просмотра из предыдущих разделов. Она читает список существующих страниц с сайта. Для записи добавьте `--publish --limit N` и для включений сохраните `--manifest pages`. При создании `createonly` защищает существующие страницы. Локальный `journal.jsonl` хранит результат и ID успешной правки. При отказе сервера скрипт останавливается и показывает причину.

Смена `WS_API` сохраняет паузы между запросами. Для каждой целевой вики задайте отдельный `WS_VOLS`, поскольку журналы относятся к одной вики. Ускоренный режим `WS_TEST_MODE=1` доступен только с локальным адресом API. Для работы от своего имени задайте контакт в `WS_USER_AGENT`. [Правила использования MediaWiki API](https://www.mediawiki.org/wiki/API:Etiquette)

## Точечные и обслуживающие правки

- `bun tools/pagefix.ts DIR` считывает `DIR/fixes.json` и строит `before/`, `after/` и Markdown-diff. `--publish` запускает правки с базовой ревизией. [Пример входа](formats.md#точечные-замены)
- `bun pipeline/migrate.ts --vol 48` готовит перенос текста существующих статей на страницы индекса и собирает черновики и отчёт. Перед `--publish` сверяются страницы и заполняется `vols/48/reviewed.txt` с названиями. Сценарий обновляет страницы индекса, проверяет включение и затем обновляет статьи. Он привязан к правилам БСЭ1.
- `bun pipeline/style.ts --dir review` применяет исправления оформления к локальным файлам `review/model/*.wiki` и сообщает о замечаниях. `retouch.ts` и `restyle.ts` готовят обслуживающие правки страниц БСЭ1. Перед применением разберите предлагаемые изменения и проверьте настройки отбора в коде.
- `bun pipeline/summary.ts` составляет сводку по локальным томам и запрашивает справочники Викитеки. Классификация авторства и сроков в этом модуле предназначена для ручного разбора в проекте БСЭ1.

Для переноса в другое издание начните с [профиля](../pipeline/profile.ts), [подбора индексов](../pipeline/lib.ts), [разбора словника и шапки статьи](../pipeline/parse.ts), шаблонов и правил качества. Логику проверки границ `planTransclusion` и подсчёт расхождений `scorePage` можно вызывать напрямую из TypeScript.
